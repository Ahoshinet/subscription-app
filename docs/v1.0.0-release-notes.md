# Subscription Manager v1.0.0

Subscription Manager v1.0.0 is the first stable release of the v1 line.
Development since v0.16.0 focused on reliability, data safety, consistent
mobile behavior, regression coverage, and a reproducible release process
rather than new user-facing features.

## Highlights

### Reliability and data safety

- Added regression coverage for sign-in, registration, sign-out, session
  restoration, subscription lifecycle operations, payment methods, settings,
  reminders, Gmail transactions, Paidy state, API contracts, and shared
  utilities.
- Hardened account-scoped asynchronous state so results started by a previous
  session are less likely to affect another account after sign-out or account
  switching.
- Preserved valid stored sessions during temporary network or service failures
  instead of treating every failed startup request as an expired login.
- Added runtime validation for synchronized settings, payment method types,
  subscription and payment icons, Gmail responses, and UI selection values.
- Improved Gmail and Paidy synchronization around pagination, message parsing,
  partial failures, reauthentication, and account changes.
- Stable update checks ignore release-candidate tags and only offer newer
  stable versions.

### Mobile UI polish

- Login and registration failures now use the same native error dialogs as
  other submitted actions instead of a persistent banner that shifts the form.
- The subscription status switch now uses the same enabled color as Settings
  on iOS and Android.
- Billing Cycle and Currency picker rows keep a consistent height, and Edit
  form text remains vertically centered.
- Payment method text inputs now use consistent native font, alignment,
  capitalization, and autocorrection behavior.
- The Settings sign-out action now follows the same neutral action styling as
  the surrounding screen.
- Updated date selection, image cropping and HEIC/HEIF conversion, and
  notification response handling for the current Expo and React Native APIs.

### Quality, compatibility, and security

- Runs tests, type checking, and lint checks for pushes and pull requests, with
  enforced coverage thresholds for the core `lib/` and `store/` code.
- Added release-tag verification across the package version, displayed release
  version, native marketing version, and native build identifiers.
- Aligned Expo SDK 57 dependencies with their compatible releases and changed
  release builds to verify the committed lockfile instead of modifying
  dependencies during CI.
- Updated vulnerable transitive PostCSS and brace-expansion dependencies to
  patched versions. The production dependency audit reported no known
  vulnerabilities during final release preparation.
- Added Android performance measurement tooling and automated Android/iOS
  release artifact generation.
- Completed maintainer-confirmed real-device validation on Android and iOS.

## Breaking changes

- No known breaking changes were identified.
- The application continues to use the `/api/v1` API contract.
- Existing application storage keys were not renamed or replaced.
- Supported release platforms are Android and iOS. Web is not a supported
  release target.

## Upgrading from v0.16.0

The release is designed as an in-place upgrade from v0.16.0 and does not
introduce an application storage migration. A separate repository record for
the v0.16.0-to-v1.0.0 upgrade test was not provided, so this note does not claim
that every stored-state combination was exercised.

Gmail and Paidy access tokens are stored on the device. After reinstalling the
app or moving to another device, sign in to Google again before synchronizing.
Previously parsed summary data associated with the account can still be
restored from the service.

## Known limitations

- The GitHub Release iOS artifact is an unsigned IPA. Installation requires
  AltStore, Sideloadly, or another sideloading method.
- Gmail / Paidy automatic import remains a beta feature and currently requires
  a tester invitation.
- Google access tokens expire and may require reauthentication before the next
  synchronization.
- Web is not a supported release platform.
